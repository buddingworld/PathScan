# PathScan

递归型 Web 目录/文件扫描器。多线程、连接复用、带探测机制，用于在目录/文件数量
较大的场景下快速枚举 Web 路径。

## 快速开始

```bash
python pathscan.py -u http://target.com -d d.txt -f f.txt
```

`-d` 与 `-f` 都是必需参数（按规格要求）。最小可用命令：

```bash
python pathscan.py -u http://target.com -d d.txt -f f.txt -s .php,.html
```

## 完整参数说明

```bash
python pathscan.py --help
```

`--help` 里除了分组列出的参数表，还有逐参数说明与示例（掩码写法、规则写法等）。
参数缺失或出错时也会附带常用命令示例：

```
Common Commands:
  Common IIS: pathscan.py -d d.txt -f f.txt -s .aspx --cs 0
  Common JSP: pathscan.py -d d.txt -f f.txt -s .jsp --cs 1
  Common PHP: pathscan.py -d d.txt -f f.txt -s .php --cs 1
  Full   IIS: pathscan.py -d d.txt -f f.txt -s .aspx,.ashx,.asmx --cs 0 --ed ?1?1?1?1,pinyinpinyin.txt --cs1 ?h?H
  Full   JSP: pathscan.py -d d.txt -f f.txt -s .jsp --cs 0 --ed ?1?1?1?1,pinyinpinyin.txt --cs1 ?h
```

## 实时日志与最终报告

扫描中每完成一次请求打一条实时日志：

```
ThreadID:0  ->    /admin [200]
ThreadID:1  ->    /nope1 [404]
ThreadID:2  ->    /gone  [err]
```

中括号里是**服务器返回的状态码**（`200` / `301` / `404` / `403` …），
只有网络层失败（连不上、超时、连接被重置）才显示 `[err]`——那时压根没有
状态码可显示。比笼统的 `[err]` 有用得多：一眼能看出 404 与 403 的区别。

路径不足 40 字符时补空格对齐，超过 40 字符原样输出（此时不对齐）。
尾部附加 `Speed: {n}/s`（10 秒窗口内请求数 ÷ 10，为估算值，开销可忽略）。

备注非空时会追加在行尾（见下方词表格式的 `remark` 字段）。

非命中行（404、被 `--ir` 判为 404、网络失败）只是「路过」，会被后续请求原地覆盖；
命中行会固定下来，之后的日志另起新行。重定向到文件或管道时自动关闭覆盖，
且只保留命中行，避免日志被 404 刷爆；`--cq` 可完全关闭实时日志。

**实时日志只输出到屏幕，不会写进 `--of` 的文件**——导出文件里只有汇总报告。

扫描结束后输出汇总报告（同时写入 `--of`）：

```
http://target/
Ignored Paths:
    /admin/panel  [200] (1820)
Result(OK):
    /admin  [200] (10)
    /api    [301] (0) -> /api/v2
```

`Ignored Paths` 只列**被 dircheck 判为软 404 的目录**（`reason` 为
`dircheck soft 404`），也就是「这里没继续往下扫」的原因；`--ir` 命中的路径
与普通 404 完全一致，不记录、不出现。

`(size)` 优先取 `Content-Length`，没有则取 `len(response.content)`。
两个小节都只列目录，见下文「最终报告里只列目录」。

## 扫描中暂停

按 `Ctrl+C` 暂停，暂停后进入指令提示符（`pathscan> `）。暂停提示会另起新行，
不会和实时日志挤在同一行：

| 指令 | 说明 |
|---|---|
| `rp <前缀>` | 移除已扫描出结果的路径，前缀匹配。`rp admin_x` 会清掉 `admin_*` |
| `at <n>` | 增加 n 个线程；n 为负数表示减少 |
| `status` | 显示当前进度、速率、线程数 |
| `exec <代码>` | 临时执行代码，如 `exec test_list.add(123)` |
| `go` | 继续扫描 |
| `pause` | 保持暂停 |
| `stop` | 终止扫描 |
| `ed <dirs>` | 追加额外目录，逗号分隔。**已扫过的每个目录**都会补上这些子目录，不影响已有结果 |
| `cs <0\|1>` | 切换大小写敏感 |
| `od <dir>` | 追加已知存在的目录，逐层检查并补上，直接认定为非 404 且参与递归 |
| `help` | 显示帮助 |

暂停中再按一次 `Ctrl+C` 直接退出。

## 词表格式

一行一个条目，`名称#备注`，备注是 JSON：

```
admin
backup#{"waf":3}
rootonly#{"r":"0-1"}
tagged#{"remark":"ZhiyuanOA"}
```

| 字段 | 说明 |
|---|---|
| `waf` | 该名称易被 WAF 拦截的阈值。同一名称的失败次数超过该值后全局不再扫描。默认 `0` = 不检测 |
| `r` | **仅在这些层级测试**。`"0-1"` 表示 0~1 层，`"2"` 表示只测第 2 层，`"1-"` 表示 1 层及以上。层数按目录算：`/test` 是 1 层，`/xx/test` 是 2 层 |
| `remark` | 备注文本。**仅在该路径请求结果非 404**（含未被规则视为 404）时，追加显示在实时日志与最终输出行尾。与备注的值无关 |

**名称两端的斜杠会被去掉**（`admin/`、`/admin` 都按 `admin` 处理），`--ed` /
`--ef` / `ed` 指令同理。带着尾斜杠进队列，目录命中后拼备份后缀会生成
`admin/.zip` 这种「文件名是空的、只剩个后缀」的路径——这种路径压根不该存在，
所以从入口就归一化，生成器另有一层兜底。

`r` 字段的例子：

```
test#{"r":"0-1"}      # /test 会测，/admin/test 不会
deep#{"r":"2-"}       # 只在第 2 层及更深测
mix#{"remark":"后台","waf":3,"r":"0-2"}
```

`remark` 的显示例子：

```
admin#{"remark":"后台管理"}   # 返回 200 -> 显示
Ignored Paths: 里的条目不显示    # 被判为 404 的路径
```

实时日志：

```
ThreadID:1  ->  /admin    [200]  Speed: 0.9/s  #后台管理
```

### 最终报告里只列目录

`Ignored Paths` 与 `Result(OK)` 两个小节都**只列目录**：

- 目录代表「这里没继续往下扫」（被 dircheck 判为软 404）或「这里存在」，
  是报告真正要传达的信息；
- 文件和备份路径数量极大（一个目录就有上千个备份任务），逐条列出会把
  报告刷满，它们的结论与普通 404 相同——只在实时日志里留一行 `[err]`。

**`--ir` 命中的路径与普通 404 完全一致**：不记录结果、不递归，也不进
`Ignored Paths`。软 404 站点上大部分请求都会命中规则，留痕只会让报告变成
一屏「全是 404」，而它传达的信息和一行业务日志没有区别。

被 dircheck 判为软 404 的目录则转入 `Ignored Paths`（`reason` 为
`dircheck 软 404`）——这是「为什么不往下扫」的唯一留痕处。

## 扫描顺序

分三个阶段，先铺完目录树再集中扫文件：

| 优先级 | 内容 | 说明 |
|---|---|---|
| 1（最高） | 探测任务 | dircheck / 后缀检测。必须最先跑，否则延迟组无法放行 |
| 2 | 目录 | 整棵目录树先展开，才能发现所有子目录 |
| 3（最低） | 文件 | 等没有待处理/在途目录且探测全部结算后，才集中扫 |

队列内部按优先级分桶（FIFO 桶），出队时取最高优先级的非空桶，入队与出队
都是 O(1)。

「目录阶段结束」的判定要求三者同时满足：队列里没有目录任务、没有在途的
探测/目录请求、没有等待结算的探测。任一不满足就会压住文件任务继续等，
这样不会因为某个子目录还没展开就提前开始扫文件。

`status` 指令会按优先级显示队列积压：

```
 done 1234  queued 56 [probe 2 / dir 8 / file 46]  active 4
```

## 探测机制

扫描开始时、以及每进入一个新目录时，会先发两类探测，根据结论决定后续扫什么。
**常规任务与备份任务会暂存在队列外，等探测出结论后再放行**，避免探测还没回来就
把上千个任务扫掉。

| 探测 | 做法 | 结论 |
|---|---|---|
| 目录探测 | 请求 `{随机8位}`（纯随机名，不带后缀） | 若返回存在，说明服务器对任意路径都返回 200（软 404），该目录下所有路径按 404 处理；**根目录命中则终止扫描**，终止前输出关键请求的响应关键信息（`status_code` / `content_length` / `content_type` / `server` / `location`） |
| 后缀检测 | 对每个待用后缀请求 `{随机8位}{后缀}` | 只要返回的不是「不存在」（404 类），该后缀的响应就不可信（万能 200 或 WAF 对这类后缀一律 403），整个目录不再扫该后缀 |

**后缀检测覆盖本轮会用到的全部后缀**，不只是 `-s` 列的：

* `-s` 列出的后缀（常规文件任务按它们展开）；
* `--files` 词表里出现的后缀（那些名字自带后缀，不经过 `-s`）；
* **备份文件的后缀**（`db.zip`、`web.log`、`admin.bak` …）——备份任务同样是
  文件任务，走同一道「这个后缀可不可信」的闸门。少了这一项，`.log` 这类
  被 WAF 拦的后缀整轮都没被验证过，`db.log`、`web.log` 会一遍遍撞墙。

命中后该后缀整轮跳过：提示形如
`! suffix .log under / is untrustworthy (code:403), skipping it`。
结论沿目录树复用（同一站点后缀可用性几乎不随目录变化），所以每个分支只在
最上层探一轮；`--nb` 不生成备份任务，也就不再探备份后缀。
| 目录自身备份 | 目录确认存在后追加 `{目录名}{后缀}` | 如 `/admin/web/` 存在则探 `/admin/web.zip`、`/admin/web.tar.gz` 等，`from=backup_suffix` |

**备份文件不另设探针**。曾经用「随机名 + 具体后缀」（`__probe__xxxxxxxx.log`）
逐后缀探测服务器是否放行，但这类名字几乎必被 WAF 拦（`.log` / `.env` / `.bak`
都是敏感后缀），而探针优先级最高、开机第一批就是它们，规则一拦整个扫描还没出
结果就卡住了。备份文件该不该信，交给 dircheck（纯随机字符串）与 `--ir` 判断。

目录被判软 404 后，这个结论是**立即生效、全面生效**的：

* 同批入队的后缀探针不再发出（已在途的静默结算，不报「命中/跳过」）；
* 该目录及其下所有路径已记录的命中全部撤回——它们是这个假目录的产物，
  转记入 `Ignored Paths`。

提示只有一行，形如：

```
! /xx1/xx2 soft 404 for /xx1/xx2/wwwwwwww code:200 len:1820, withdrew 3 result(s)
```

即「哪个目录被判定为软 404 / 依据是哪次探测 / 服务器回的什么」；
`withdrew N result(s)` 只在确实撤回时出现。

否则会出现「dircheck 判定软 404」与「后缀探针 `Login/error/.zip` 命中」并存、
以及 `/Static/fonts/zz` 这类已被判死的子目录照样列在结果里的怪象。

目录自身备份的后缀列表：`.gz .7z .zip .rar .tar .bak .sql .txt`。
它与递归深度 `-r` 无关——目录已经确认存在，其备份是叶子文件，因此不受层数限制。

**`--nb` 关闭全部自动备份路径**：备份文件（名称×后缀）与目录自身备份都不再
产生，备份后缀也就不再探测，只保留 dircheck 与 `-s` / `--files` 的后缀检测。
词表里自己写的备份名照常扫。

**标注了 `waf` 的目录不扫自身备份**：备份名带着同一个敏感串
（`.svn` → `.svn.zip`、`.svn.bak`），照样会触发那条 WAF 规则；而 WAF 打回的
`403` 不在「不存在」状态码里，会被记成一堆假命中，还继续喂检测规则。
该目录本身已计入结果，少了备份不会漏掉它存在的证据。
判据是「条目标了 `waf`」而不是「已被拉黑」——`waf` 是阈值，`waf=1` 要失败
两次才拉黑，按拉黑判断会漏掉第一次命中。

**父目录被拉黑/忽略后，整棵子树不再发请求**。名称过滤只比对任务自己的名字，
`actuator/.zip` 这种子路径的名字里不含敏感串，会整批漏网；可目录都被拉黑了，
它下面的请求发出去只会再喂一遍那条 WAF 规则。路径逐段回溯，命中即跳过。

## `--od` 与伪 404

`--od dir1/dir2/dir3/` 逐层登记，每层**只发一次 dircheck**（不发后缀探测，
用户已确认存在）：

* dircheck 通过 → 该层按正常目录展开整份词表；
* dircheck 命中（伪 404 区）→ **不展开该层的词表子目录**（`dir1/xx1`、`dir1/xx2`
  全是无效访问），该层从结果撤回、转记 `Ignored Paths`；
* 无论哪种情况，**od 链继续往下走**：dir1 是假的也不影响 dir1/dir2、dir1/dir2/dir3，
  用户明确说了它们存在；
* **路径的每一段同时并入 `--ed`**：dir1、dir2、dir3 在根目录下各按普通目录测一次
  （完整探测 + 递归）。名字已在 `--ed` 里时不再重复请求该层自身。

**后缀一律按「最后一个点」解析**：`.tar.gz` 视为 `.gz`，`.sql.gz` 也视为 `.gz`。
所以后缀列表里只列单点后缀，像 `.tar.gz` 这类写法永远不会被匹配到。

备份名由基础名表 + 域名派生名组成。域名会按 `_` / `.` / `-` 连接符做子集组合
（`abc.google.com` → `abc`、`google`、`abc.google` 等，共 48 个）；**IP 目标不做
排列组合**，只保留完整 IP 的四种写法（`127.0.0.1` / `127001` / `127_0_0_1` /
`127-0-0-1`，共 37 个），因为 `0-0-1` 这类子集组合命中率为零。

后缀检测会沿上级目录复用结论：同一站点后缀可用性几乎不随目录变化，
祖先目录已探明的后缀不再重复探测。

## WAF 自动检测与线程自保

三个机制都会自动生效，不需要额外参数。

### 名称级 WAF 检测

某个路径的**失败次数**（网络层失败，不含 404）累计超过 2 次时，把它的 `{name}`
放进计数器观察 **5 秒**。窗口结束时统计：

* 计数器里**只有它自己** → 判定该名称触发了 WAF，加入忽略列表，后续不再检测；
* 计数器里**还有别的名称** → 只把当前项移除（是站点的普遍问题，不是这个名称）。

### 线程级自保

每个线程维护一个连续失败计数器：请求成功清零，失败 +1。
累计超过 **5** 次时该线程惩罚性暂停 **30 秒**。30 秒后：

* 其他线程**也都在暂停** → 视为 IP 被整体封禁，转入 WAF 拦截等待模式；
* 其他线程**都正常**（失败计数为 0）→ 该线程继续跑。

### WAF 拦截等待模式

表现与按 `Ctrl+C` 暂停相同（暂停扫描、可敲指令），但会检测按键：

* **有按键** → 进入指令模式，由你决定 `go` / `stop`；
* **30 分钟内无任何按键** → 视为无人值守，自动 `go` 恢复扫描。

`status` 指令会显示实时速度、连续失败中的线程、以及被 WAF 忽略的名称。

| 参数 | 默认 | 说明 |

| `-u` | 必填 | 目标 url |
| `-t` | 3 | 线程数 |
| `-m` | head | 请求方法 `get\|post\|head\|...` |
| `-r` | 5 | 递归最大层数 |
| `-d` | 必填 | 目录词表文件 |
| `-f` | 必填 | 文件名词表文件（不含后缀） |
| `--files` | — | 带后缀的文件词表 |
| `-s` | — | 文件后缀，逗号分隔，如 `.php,.aspx`。同时驱动后缀探测 |
| `--file-pre` | — | 文件前缀，逗号分隔，如 `old_,new_` |
| `--ed` | — | 额外目录，支持掩码 |
| `--ef` | — | 额外文件，支持掩码 |
| `--cs1`..`--cs9` | — | 自定义字符集 `?1`~`?9`，各自独立，可嵌套 `?l?d` |
| `--csc` | — | 组合扩展的连接字符，如 `",_,-"` |
| `--rh` | — | 请求头，可多次，如 `--rh "Cookie: a=b"` |
| `--mode` | 2 | 1=目录补 `/`，2=不补 |

| `--ti` | 0 | 线程内请求间隔，如 `1`、`0.2`、`1-3`（区间随机） |
| `--od` | — | 已确认存在的目录，形如 `dir1/dir2/dir3/`。逐层登记并参与递归；每层只发一次 dircheck（伪 404 的层不展开其词表子目录，但链继续往下走）。**路径的每一段也会并入 `--ed`**，即 dir1 / dir2 / dir3 在根目录下各按普通目录测一次。可多次 |
| `--of` | — | 结果导出路径 |
| `--ir` | — | 忽略规则，2 参数可多次：`--ir <属性> <值>` |
| `--br` | — | 排除路径规则，2 参数可多次：`--br <属性> <值>` |
| `--nb` | — | 不自动添加备份路径：不扫备份文件（名称×后缀）、不追加目录自身备份。词表里手写的备份名不受影响 |
| `--proxy` | — | 代理，支持 `http/https/socks5/socks5h`。**不指定时完全不用代理**，环境变量与系统代理设置都会被忽略 |
| `--ka` | 200 | 复用次数：`0`=无限，`N`=复用 N 次后重连，负数=不复用 |
| `--rt` | 3 | 请求最大失败重试次数 |
| `--timeout` | 10 | 单次请求超时秒数 |
| `--bh` | — | bypass headers 测试，**待开发**，当前解析后忽略 |
| `--cq` | — | 安静模式，只输出结果 |
| `--debug` | — | 输出诊断信息（探测结算、`--od` 登记、延迟组放行等） |

### `--ir` 属性

把匹配到的响应判定为 404：不记录结果、不继续递归、不进最终报告，
与普通 404 的唯一区别是进度日志里的 `[err]` 行（`--debug` 时另有一行诊断）：

- `code` 状态码，支持区间 `404` / `100-200`
- `size` 响应长度，优先 `Content-Length`，没有则取解压后 body 的**字节数**（`len(r.content)`，不是解码后的字符数）
- `grep` 响应体正则匹配
- `text` 响应体文本匹配
- `location` 301/302 跳转的目标 url

规则同样作用于**探针请求**：软 404 服务器用「200 + 固定长度错误页」回应时，
用 `--ir size` 声明该错误页长度即可让 dircheck 判为「随机路径不存在」，
扫描照常继续，而不是识别成软 404 后终止。

```bash
# 把长度恰好 1234 的响应当作 404
python pathscan.py -u http://t -d d.txt -f f.txt --ir size 1234
# 软 404：错误页 1800-1900 字节，声明为 404 后继续扫描
python pathscan.py -u http://t -d d.txt -f f.txt --ir size 1800-1900
```

### `--br` 属性

路径命中则不入队：`name`（默认）、`path`、`url`。

```bash
# 路径里含 logout 的一律不扫
python pathscan.py -u http://t -d d.txt -f f.txt --br name logout
```

## 代理

只有 `--proxy` 显式指定时才走代理：

```bash
--proxy http://127.0.0.1:8081
--proxy socks5h://127.0.0.1:1080
```

**未指定时不读环境变量，也不用系统代理。** requests 默认 `trust_env=True`，
会去读 `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY`，Windows 上还会读注册表里
的系统代理设置。扫描目标通常在内网，被系统代理劫持会让请求全部失败或走到
错误的出口，所以扫描器显式关闭了这个行为（顺带也不再读 `.netrc`，避免悄悄
套用本机凭据）。

## 已知存在的目录（--od）

`--od dir1/dir2/dir3/` 会把路径的**每一层**都直接判定为存在，不经过探测：

```
--od admin/backend/
  等价于认定 admin/ 、admin/backend/ 都存在
```

这些目录会：

* **请求它自身** —— 逐层的每一级都会真的发一次请求，所以存在的目录一定会
  出现在结果里。这一点很关键：`--od` 只负责「打开目录以便向下递归」，
  若不额外请求自身，就只有词表里的同名条目能请求到它；
* **参与递归** —— 其下的子目录/文件按正常流程扫描；
* **跳过探测** —— 不发 dircheck / 后缀检测 / 备份探测请求。

逐层登记的意义在于补齐中间层：如果词表里没有 `admin`，只写
`--od admin/backend/` 也能让扫描从 `admin/backend/` 往下正常展开，不会断链。

扫描仍然从 `/` 开始：`--od` 目录会等根目录探测结算后再登记，且词表条目
先于备份任务放行，不会把词表推到很后面。

排查 `--od` 是否生效时加 `--debug`：

```
* 根目录探测结算完成（probe_wait=空），开始登记 --od 目录
  · --od 登记 'tc'
  · --od 直接放行目录 'tc/member'（常规 4 / 备份 1184）
```

```bash
# 已知后台在这两个路径下，直接跳过探测从这些目录开始铺开
python pathscan.py -u http://t -d d.txt -f f.txt   --od admin/backend/ --od manage/console/
```

也可以逗号分隔：`--od admin/backend/,manage/`。

## 掩码

`--ed` / `--ef` 支持 hashcat 风格掩码与组合扩展：

```bash
# admin1 admin2 admin3, devtest / dev_test / dev-test
python pathscan.py -u http://t -d d.txt -f f.txt \
  --ed 'admin?d,{C-2:dev,test}' --csc ',_-'
```

| 语法 | 含义 |
|---|---|
| `?l ?u ?d ?s ?a ?b ?h ?H` | hashcat 标准字符集 |
| `?1`..`?9` | 自定义字符集，由 `--cs1`..`--cs9` 定义，可嵌套 |
| `{C-2:dev,test,prd}` | 取 2 个做**组合**（顺序无关） |
| `{P-2:dev,test,prd}` | 取 2 个做**排列**（顺序有关） |
| `{dev,test,prd}` | 任取一个 |

`--csc` 指定连接字符；空串总是隐含包含，所以 `--csc ',_'` 会同时产出
`devtest` 和 `dev_test`。

## 架构

```
pathscan.py          入口：参数解析 + 启动 + 收尾导出
pathscan/
  cli.py             全部参数定义、校验、词表读取
  mask.py            hashcat 掩码 + {C-n}/{P-n} 组合扩展
  models.py          Task（对应规格的 JSON）、GlobalState、TaskQueue
  probes.py          dircheck / 后缀检测 / 备份文件生成
  scanner.py         每线程一个 Session，连接池与 --ka 复用控制
  engine.py          队列、线程池、递归展开、探测结算
  control.py         Ctrl+C 暂停 + 指令 REPL
  output.py          结果渲染与 --of 导出（cp936 安全的输出层）
  rules.py           --ir / --br / --cs
```

### 队列任务格式

任务与规格里的 JSON 一一对应，可无损往返：

```json
{"type":"dir","trytimes":0,"name":"admin","parent":"",
 "from":"dircheck","remark":"","waf":3}
```

`from` 取值：`common`（常规）、`suffixcheck`（后缀检测）、`dircheck`（目录检测）、
`backup`（备份文件）、`backup_suffix`（目录自身备份）、`okdir`（--od 目录）、
`ed`（ed 指令）、`exec`（暂停时 exec 指令塞入）。

### 关键实现说明

- **结束判定**用待完成计数而不是「队列为空」。探测任务还在飞行时队列可能是空的，
  只看队列会提前退出。
- **探测结算在锁内完成**：先把放行的任务计入待完成数，再从暂存区摘掉，
  避免其他线程在中间窗口误判扫描结束。
- **探测任务失败也会结算**。网络不通时不能硬推断服务器行为——那会静默漏掉
  整个目录的结果，所以失败时保守放行。
- **重试由调度器控制**（`max_retries=0`），requests 内部不重试，避免两套重试叠加
  把 `--rt` 的语义放大。
- **输出层对 cp936 控制台做了防护**，打印非 ASCII 路径不会崩。
